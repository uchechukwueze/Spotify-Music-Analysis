### Introduction
In today’s music industry, a song is no longer judged only by how good it sounds. Its success is measured by how far it travels, how many people stream it, how many viewers engage with its video, how strongly listeners react to it, and whether it can keep performing across different platforms.

With millions of tracks competing for attention, music labels, artists, streaming platforms, and content managers need more than guesswork. They need data-driven insight to understand **which songs are winning, which artists are dominating, what type of albums perform best, and how audio features like energy, danceability, and liveness influence audience engagement**.

This project uses a Spotify dataset containing track, artist, album, streaming, YouTube engagement, licensing, and audio-feature information. The goal is to transform raw music data into meaningful business insights that can support decisions around artist promotion, playlist strategy, content licensing, and platform performance comparison.

---

### Business Problem

A music analytics company wants to help record labels and streaming managers understand how songs perform across Spotify and YouTube.

The company needs answers to important business questions such as:

* Which tracks have achieved massive commercial success with over 1 billion streams?
* Which artists have the strongest catalogue based on number of tracks and views?
* Which albums and album types generate the highest listener engagement?
* Are official videos performing better in terms of views and likes?
* Which songs perform better on Spotify compared to YouTube?
* What audio characteristics are common among highly performing tracks?
* Which artists have the top-performing tracks based on views?
* How do features like danceability, energy, liveness, and duration relate to audience engagement?

Without structured analysis, these insights remain hidden inside thousands of rows of music data. This makes it difficult for decision-makers to know where to invest promotion, which artists to prioritize, which tracks to license, and which songs have the strongest cross-platform impact.

---

### Project Objective

The objective of this project is to use SQL to analyze Spotify music performance data and generate insights that can help music stakeholders make smarter business decisions.

Specifically, the project focuses on:

1. Understanding the structure and size of the dataset.
2. Exploring track, artist, album, and platform performance.
3. Identifying high-performing songs based on streams, views, likes, and comments.
4. Comparing Spotify streaming performance with YouTube performance.
5. Analyzing audio features such as danceability, energy, liveness, and instrumentalness.
6. Using advanced SQL techniques such as aggregation, filtering, CTEs, and window functions to answer business questions.

---

### Solution Approach

To solve the business problem, I created a PostgreSQL database and imported the cleaned Spotify dataset into a structured table. I then used SQL queries to extract insights from the data.

The analysis was divided into three levels:

### 1. Basic Business Understanding

At this stage, I explored the dataset to understand the available records and answer simple but useful business questions.

This included:

* Retrieving tracks with more than 1 billion streams.
* Listing albums with their respective artists.
* Calculating total comments for licensed tracks.
* Identifying tracks released as singles.
* Counting the total number of tracks by each artist.

These queries helped build a foundation for understanding the dataset and identifying the most active artists, albums, and track categories.

### 2. Performance and Engagement Analysis

The next stage focused on measuring how songs perform across platforms.

I analyzed:

* The average danceability of tracks in each album.
* The top 5 tracks with the highest energy scores.
* Tracks with official videos and their corresponding views and likes.
* Total views generated by each album.
* Tracks that performed better on Spotify than on YouTube.

This helped uncover which songs and albums attracted stronger audience attention and which platform delivered better performance for specific tracks.

### 3. Advanced SQL Analysis

The final stage applied advanced SQL concepts to generate deeper insights.

This included:

* Using window functions to find the top 3 most-viewed tracks for each artist.
* Identifying tracks with liveness scores above the overall average.
* Using CTEs to calculate the difference between the highest and lowest energy values for tracks in each album.
* Finding songs with an energy-to-liveness ratio greater than 1.2.
* Calculating the cumulative sum of likes based on track views using window functions.

These advanced queries helped move the project beyond simple reporting into deeper music performance intelligence.

### List all tracks along with their views and likes where official_video = True
```sql
SELECT
track,
sum(views) as total_views,
sum(likes) as total_likes
FROM spotify
where official_video = 'true'
GROUP BY track;
```

### For each album, calculate the total views of all associated tracks
```sql
SELECT 
distinct album,
track,
sum(views)
FROM spotify
GROUP BY album, track;

SELECT 
album,
track,
sum(views) as total_views

```

#### Retrive the track names that have been streamed on Spotify more than YouTube
```sql
SELECT * FROM
(select
	track,
	--most_played_on,
	 COALESCE(SUM(CASE WHEN most_played_on ='Youtube' THEN stream END),0) as steam_on_youtube,
	 COALESCE(SUM(CASE WHEN most_played_on ='Spotify' THEN stream END),0) as steam_on_spotify
from spotify
GROUP BY 1
) as t1
WHERE 
	steam_on_spotify > steam_on_youtube
	AND steam_on_youtube <> 0
```

#### Find the top 3 most_viewed tracks for each artist using windom functions
```sql
WITH rankings_artist
AS
(SELECT 
	artist,
	track,
	sum(views) as total_views,
	DENSE_RANK() OVER(PARTITION BY artist ORDER BY SUM(views) DESC) as RANK
FROM spotify
GROUP BY 1, 2
ORDER BY 1, 3 DESC)
SELECT * FROM rankings_artist
WHERE rank <=3
```

```sql
#### Write a query to find tracks where the liveness score is above the average

SELECT
track,
liveness
FROM spotify
WHERE liveness >(select avg(liveness)from spotify) -- avg liveness = 0.19
```
```sql

#### Use a WITH clause to calculate the difference btw the highest and lowesr energy values for tracks in each album

WITH cte
AS
(SELECT 
album,
MAX(energy) as highest_energy,
MIN(energy) as lowest_energy
FROM spotify
GROUP BY 1)
SELECT
album,
highest_energy - lowest_energy
FROM cte
ORDER BY 2 DESC;
```

#### Find tracks where the energy-to-liveness ratio is greater than 1.2
```sql
SELECT
track,
energy /liveness as energy_to_liveness_ratio
FROM spotify
WHERE energy /liveness > 1.2
ORDER BY 2 DESC;
```
